# 校园集市 · 学生二手交易平台

一个只服务本校学生的二手交易网站。学生用手机号注册、填写学校与学号，把闲置拍照挂上去；别人搜到、加进购物车、下单，双方约在线下当面交货给钱。**平台不经手钱款，只负责撮合和留痕。**

纯静态前端（原生 ES 模块，无构建）+ 微信云开发后端（一个云函数 + 云数据库 + 云存储），不需要买服务器。

---

## 现在能做什么

**首页**
- 搜索栏 + 商品瀑布列表，支持上下加载更多
- 7 个分类筛选、三种排序（最新 / 价格升序 / 价格降序）
- 顶部实时统计在售件数与今日上新

**搜索**
- 关键词同时匹配标题、描述、分类，输入片段就能命中（不用打全名）
- 空格分词：多个词用空格隔开，每个词都要出现（如「考研 数学」）
- 忽略大小写与全半角差异（`ipad` 能搜到 `iPad`，`ＩＰＡＤ` 也行）
- 只搜在售商品；有结果统计文案，无结果给空状态引导

**商品**
- 详情页：多图切换、完整描述、卖家信息与联系方式、浏览量
- 发布：标题、分类、价格、数量、描述、最多 5 张图，提交后进入待审核

**购物车与下单**
- 加购、改数量（受库存限制）、勾选、删除、合计
- 结算填面交地点与电话，一键带出保存过的地址
- 下单后商品自动锁定为「已预订」，别人买不到

**订单**
- 我买到的 / 我卖出的两个视角
- 状态：待面交 → 已完成 / 已取消；**买卖双方各确认一次**才算完成
- 取消后商品自动回到在售

**个人中心**
- 资料（昵称、学校、学号、联系方式）
- 在售 / 发布 / 买到 / 卖出 四项统计
- 我的发布（含审核状态与驳回原因）、我的订单、面交地址管理

**管理员后台**
- 待审核 / 在售 / 已驳回 / 已下架 四个列表
- 通过、驳回（写原因）、下架；统计看板

## 本地跑起来

**方式一：双击 `start.cmd`**（需要装过 Python），会自动开浏览器。

**方式二：命令行**

```bash
npm start          # 等价于 python -m http.server 8765 --directory web
```

或者用任何静态服务器，指向 `web/` 目录即可（ES 模块不能用 `file://` 直接打开）。

打开 <http://127.0.0.1:8765> 就是本地演示模式，数据存在浏览器 localStorage 里，随便折腾，刷新不丢。

## 接上云开发

把数据真正存到云上，看 **[docs/部署说明.md](docs/部署说明.md)**，大约 20 分钟。

核心就两步：
1. 部署云函数、建好 5 个集合、开 HTTP 访问服务；
2. 把地址填进 `web/js/config.js` 的 `CLOUD_ENDPOINT`。

填了地址前端自动切云端，留空就是本地演示，代码一行不用改。

## 测试

```bash
npm install          # 装 jsdom（只有前端测试需要）
npm test             # 后端 30 项：注册登录、发布审核、搜索、购物车、下单、双方确认、取消、驳回
npm run test:http    # 云函数 HTTP 外层 5 项：OPTIONS、坏 JSON、未知接口、CORS 头
npm run test:ui      # 前端 50 项：首页渲染、分类筛选、搜索、详情、登录拦截、加购、结算、订单、个人中心、发布校验、注册表单、管理后台
npm run probe        # 探测云端接口是否连通（只读，不写数据）
```

`npm test` 和 `npm run test:http` 不需要任何依赖，随时可以跑。

## 状态流转

**商品**

```
发布 → 待审核 ─通过→ 在售 ─下单→ 已预订 ─双方确认→ 已售出
              └驳回→ 未通过             └取消→ 在售
                在售 ─卖家/管理员下架→ 已下架
```

**订单**

```
待面交 ─买家确认 + 卖家确认→ 已完成（商品变已售出）
  └─取消→ 已取消（商品回到在售）
```

## 明确没做的（第一版范围外）

- 真实支付、资金托管、退款 —— 说好线下面交，平台不碰钱
- 站内聊天 —— 商品页直接露联系方式
- 评价、信用分、实名认证
- 推荐算法、热门榜、收藏、优惠券
- 短信/推送通知
- 多学校隔离 —— 目前按单校跑
